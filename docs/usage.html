Usage Guide

A general warning first: LOUIS is experimental and may not work as expected. Please report any problems via GitHub Issues

LOUIS can be used via two main ways: as an AI model on OpenWebUI or via its terminal chat. We recommend you use the first option, as it provides the most features and lets you re-read old chats.

Terminal Chat

Start a chat session with LOUIS using the terminal

python main.py chat

Commands:

  • /reset: Summarizes the current session and starts a new one with the summary added to its system prompt.
  • /new: Starts a clean new session.
  • /exit: Exits the chat.

Terminal chat sessions are only stored in the session files in $XDG_STATE_HOME/louis/sessions and will be removed, if you start more than 20 sessions afterwards (the last 20 are kept).
You cannot continue a finished / canceled terminal chat.

Context Window Warning

LOUIS warns you when the chat reaches a configurable percentage of the context window (recommended: 85-90%). This feature works in both terminal chat and Open WebUI.

Graph Commands

Interact with the memory graph:

  • python main.py graph show: Opens the graph view in the browser.
  • python main.py graph query: Launches an interactive graph query.
  • python main.py graph write: Launches an interactive write mode.

Cron Subcommand

Interact with Open WebUI's prompt scheduling system:

python main.py cron

This allows you to schedule prompts and manage scheduled tasks directly from LOUIS.

Open WebUI Integration

The intended way of interacting with LOUIS. You can create and delete chats as normal. Editing messages may not work as expected or lead to crashes. LOUIS is unfortunately unable to generate suggestions for either the chat title or follow ups. If you want those, you have to configure OpenWebUI to use a MistralAI model directly. You can use the full potential of scheduled prompts and the voice interactions with LOUIS.

Please note, that LOUIS' responses are not the fastest, as they are relayed to MistralAI and processed internally. Short conversational reponses should be fine, longers should be split into parts by the model (if it complies with the prompt) but tool calls or memory access take longer. LOUIS unfortunately does not support streaming responses character by character, but rather block by block. This is due to his internal workings and cannot easily be changed. Please don't ask me to do that. I won't.

Commands

OpenWebUI only supports one command: 

/reset
. This summarizes the current session to reduce the context size. You will still be able to see all prior messages, the model won't. It can only work with the summary. Editing messages before the summary MAY HAVE UNFORSEEN CONSEQUENCES LIKE CRASHES! (to be honest, I never event tested that)

Notes

  • The server can only handle one request at a time.
  • Stopping its turn before it produced a response can cause the LOUIS server to crash.
  • You can summarize your current session using /reset via OpenWebUI too, to reduce the context size of the current chat.
